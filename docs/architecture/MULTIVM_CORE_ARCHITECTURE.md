# MultiVM 核心功能架构

## 概述

MultiVM系统的核心功能包括四个关键组件：P2P网络层、共识算法、交易打包器和区块分发器。这些组件协同工作，实现跨VM的统一区块链操作。

## 核心组件架构

### 1. P2P网络层 (multivm-p2p)

**职责**：
- 节点发现和连接管理
- 消息路由和广播
- 协议转换和兼容性处理
- 网络隔离和安全通信

**技术栈**：
- libp2p-rust 作为底层网络库
- Gossipsub 用于消息传播
- Kademlia DHT 用于节点发现
- Noise protocol 用于加密通信

```text
┌─────────────────────────────────────────────┐
│               P2P 网络层                     │
├─────────────┬─────────────┬─────────────────┤
│ 节点发现     │ 消息路由     │ 协议转换         │
│ (Kademlia)  │ (Gossipsub) │ (MultiVM<->VM)  │
└─────────────┴─────────────┴─────────────────┘
```

### 2. 共识算法 (multivm-consensus)

**职责**：
- 交易排序和区块生产
- 拜占庭容错
- 跨VM状态一致性
- 分叉处理和最终性

**算法选择**：
- **PBFT（实用拜占庭容错）** - 适合许可网络，快速最终性
- **Raft** - 适合较小规模集群，强一致性保证

```text
┌─────────────────────────────────────────────┐
│               共识层                         │
├─────────────┬─────────────┬─────────────────┤
│ 提案生成     │ 投票验证     │ 最终性确认       │
│             │             │                 │
└─────────────┴─────────────┴─────────────────┘
                      │
        ┌─────────────┴─────────────┐
        │                          │
    ┌───▼───┐                 ┌───▼───┐
    │ PBFT  │                 │ Raft  │
    └───────┘                 └───────┘
```

### 3. 交易打包器 (Transaction Batcher)

**职责**：
- 从内存池收集交易
- 按优先级和费用排序
- 构建统一区块格式
- 执行预验证和状态检查

**核心流程**：
1. 监听交易池变化
2. 按gas价格/优先费排序
3. 执行状态预验证
4. 构建候选区块
5. 提交给共识层

```text
┌─────────────────────────────────────────────┐
│               交易打包器                     │
├─────────────┬─────────────┬─────────────────┤
│ 交易收集     │ 优先级排序   │ 区块构建         │
│             │             │                 │
└─────────────┴─────────────┴─────────────────┘
                      │
        ┌─────────────┴─────────────┐
        │                          │
    ┌───▼───┐                 ┌───▼───┐
    │ SVM   │                 │ EVM   │
    │ 交易   │                 │ 交易   │
    └───────┘                 └───────┘
```

### 4. 区块分发器 (Block Distributor)

**职责**：
- 接收共识确认的区块
- 转换为VM特定格式
- 分发给reth和solana进程
- 监控执行状态和反馈

**分发流程**：
1. 接收MultiVM统一区块
2. 提取VM特定交易
3. 转换为目标VM格式
4. 并行发送给执行引擎
5. 收集执行结果

```text
┌─────────────────────────────────────────────┐
│               区块分发器                     │
├─────────────┬─────────────┬─────────────────┤
│ 格式转换     │ 并行分发     │ 结果收集         │
│             │             │                 │
└─────────────┴─────────────┴─────────────────┘
                      │
        ┌─────────────┴─────────────┐
        │                          │
    ┌───▼───┐                 ┌───▼───┐
    │ Reth  │                 │Solana │
    │ 进程   │                 │ 进程   │
    └───────┘                 └───────┘
```

### 关键数据结构

#### MultiVM 统一区块格式

```rust
pub struct MultivmBlock {
    pub header: BlockHeader,
    pub transactions: Vec<MultivmTransaction>,
    pub receipts: Vec<TransactionReceipt>,
    pub state_root: H256,
    pub timestamp: u64,
    pub signature: Option<Signature>,
}

pub enum MultivmTransaction {
    Svm(SvmTransaction),
    Evm(EvmTransaction),
    CrossVm(CrossVmTransaction),
}
```

#### P2P 消息格式

```rust
pub enum NetworkMessage {
    Transaction(MultivmTransaction),
    Block(MultivmBlock),
    ConsensusMessage(ConsensusMsg),
    PeerDiscovery(PeerInfo),
    StateSync(StateSyncRequest),
}
```

## 性能目标

- **TPS目标**: 1000+ 跨VM交易/秒
- **延迟目标**: <2秒区块确认时间
- **网络效率**: >95% 消息送达率
- **资源使用**: CPU <80%, 内存 <8GB

## 安全考虑

1. **网络安全**: Noise协议加密，节点认证
2. **共识安全**: 拜占庭容错，签名验证
3. **状态安全**: Merkle tree验证，状态一致性检查
4. **进程隔离**: 沙箱执行，资源限制

## 监控和诊断

- 实时性能指标（TPS、延迟、网络带宽）
- 共识状态监控（投票情况、分叉检测）
- 节点健康检查（连接状态、同步进度）
- 执行引擎状态（处理队列、错误率）
